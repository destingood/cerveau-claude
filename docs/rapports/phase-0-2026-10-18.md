   - Le niveau « droits Unix » est assuré par `infra/windows/protect-live.ps1`, qui n'est pas encore exécuté (à lancer en administrateur, voir section 7). Sur le VPS, ce sera `chmod 444`.
2. **Démonstration du refus.** Elle a été faite par rejeu des hooks, pas en session réelle (voir section 3).
3. **Revue de sécurité (section 13).** Je l'ai faite moi-même avec la checklist de `.claude/agents/security-reviewer.md`, sans lancer le subagent : les agents du projet n'étaient pas chargés dans cette session.
   - Constat MAJEUR : tout `.claude/` est nouveau, donc la checklist exige ta validation.
   - Constat mineur : une entrée de hook illisible est refusée mais n'est pas journalisée.
   - Aucun constat BLOQUANT.
4. **Droits des subagents.** `Write` a été ajouté à `eval-engineer` et `plugin-builder` : ils doivent créer des fichiers (tests, manifestes).
5. **Prompt système anticipé.** `core/orchestrator/prompts/system.md` (Annexe D, copie mot pour mot) est un livrable de la phase 1. Il est déjà versionné mais n'est branché nulle part.
6. **Correctif CLI hors spécification.** La sortie est forcée en UTF-8, car une sortie redirigée sous Windows passait en cp1252. Un test couvre ce cas.
7. **`governance/approvals/` non versionné.** Je n'y ai pas mis de `.gitkeep`, car ce dossier est réservé à Lucas (section 8). Le dossier sera créé par toi.

### 5. Risques ouverts et dette technique

- **Contournements connus des garde-fous** (modèle de menace § 5, backlog B1–B7) :
  - scripts lancés via `bash x.sh`, `pwsh -File` ou `python x.py` ;
  - effets de bord de git : `stash`, `pull`, `checkout <branche>` ;
  - archives préparées ailleurs ;
  - fuites Docker : `compose config` sans `--quiet`, `inspect`, `exec … env` ;
  - outils MCP hors matchers ;
  - `.claude/` lui-même non protégé.

  Les hooks restent un garde-fou de confort. La protection effective sera l'ACL, qui n'est pas encore posée.
- **Licences :**
  - MinIO est en AGPL et son dépôt est archivé depuis le 2026-04-24 (B15) ;
  - `redis:7` (7.4.11) est sous RSALv2/SSPLv1, avec Valkey comme alternative (B16) ;
  - Langfuse `ee/` est hors MIT et non utilisé ;
  - vectorbt est sous Commons Clause, réservé à un usage personnel.
- **OpenBB :** le nom `openbq-org/OpenBB` de l'Annexe A est suspect. Il faut repartir de https://docs.openbb.co (B21).
- **Chaîne de livraison :**
  - images Docker épinglées par tag, pas par digest (B11) ;
  - actions GitHub non épinglées par SHA (B10) ;
  - pas de `npm audit` ni de contrôle automatique des licences (B13) ;
  - jambe ubuntu de la CI jamais exécutée (B14).
- **Ancrage du journal :** il est local. Un attaquant qui contrôle le poste peut réécrire toute la chaîne. Un ancrage hors machine est prévu (B8).
- **Inscriptions Langfuse :** elles sont ouvertes par défaut. Il faudra les fermer après la création du premier compte (B17).
